01
Problem Statement

FormSG Collects Data — But Has No Registration State

Agencies use FormSG for event sign-ups. Once submitted, everything else is manual.

No Atomic State

No capacity enforcement, no waitlist, no status tracking at registration time.

Manual Operations

Approval, payment, reminders, attendance — all via email chains and Excel.

No Audit Trail

No record of who approved whom. IM8 requires actor-level accountability.

GovEvent — every rule enforced server-side, every action in an immutable audit trail.

Server-Side Eligibility

Domain, blacklist, capacity enforced atomically. $transaction() prevents races.

Automated State Machine

PENDING → Approve → Payment → Check-in → No-Show. Every transition triggers email + audit.

Integrated & Auditable

Stripe + Resend + Cron connected. Immutable audit log. GCC-portable container.

Key Patterns

  • Atomic insert — $transaction() prevents double-booking
  • Admin routes — requireAdmin() session check
  • Cron routes — CRON_SECRET header protection
  • Email — best-effort, never blocks state

Integrations

Stripe
App → Stripe → Webhook → App

Admin approves → create Checkout Session → participant pays → webhook verifies signature + checks isCancelled → status updated to APPROVED.

Resend
App → Resend → Participant

Confirmation, approval, rejection, payment link, T-48h reminder, OTP verification, admin broadcast. Best-effort — never blocks state changes.

Cron
Cron → App → DB (hourly)

T-48h reminders to APPROVED. Mark unchecked-in as NO_SHOW → auto-blacklist at ≥5. Expire PENDING_PAYMENT after 24h → promote waitlist. All idempotent via flags.

04
Data Flow

Registration Lifecycle — End-to-End State Machine

Core
Register → PENDING → Admin reviews → APPROVED / REJECTED / WAITLISTED
Payment
PENDING_PAYMENT → Stripe pays ✓ → APPROVED or 24h → PAYMENT_FAILED → waitlist promoted
Event Day
APPROVED → QR scan → ATTENDED or absent → NO_SHOW → ≥5 → Blacklisted

Notifications

Every transition → Resend email + audit log entry.

Waitlist

Auto-promotes when seat opens (cancel / reject / timeout).

Certificate + Concurrency

ATTENDED → printable A4 certificate (CPD hours). $transaction() — atomic capacity, no double-booking.

05
Features, Scope & Production Readiness

What's Built, What's Scoped, and What Production Would Require

Feature Highlights

  • Featured Events — admin-managed hero display on public listing page with ★ toggle
  • CPD Hours Tracker — auto-calculated from attended events, shown to logged-in participants
  • Event Certificates — formal A4 landscape, government-style, print-optimised with @media print
  • QR Check-in — camera scanner via @zxing + name/email search fallback + live stats polling
  • Blacklist System — auto-triggered at ≥5 no-shows, manual add/remove, blocks registration at submit
  • Save as Draft — dual action: "Save as Draft" + "Create & Publish" for event creation
  • CSV Export — download all registrations for an event
  • Bulk Approve — select multiple registrations, approve in one action
  • Admin Broadcast — email all APPROVED/WAITLISTED participants

Design System

"The Ethereal State" — glassmorphism, Manrope/Inter typography, Material Design 3 colors. Built from Stitch mockups → Claude Code agents.

Prototype Scope

  • Single agency (not multi-tenant)
  • Unclassified data only
  • Email as participant identifier
  • Admin managed by Super Admin
  • Stripe test mode

Known Limitations

  • No Singpass/Corppass
  • No real-time push (polling)
  • No multi-level approval
  • No automated tests
  • No PDPA retention policy
  • Single-region (no HA)

For Production

Compliance
  • Singpass/Corppass — national identity, no fake registrations
  • PDPA — data retention + impact assessment
  • DSS + WCAG 2.1 AA — government accessibility
  • IM8 — security classification before go-live
Security
  • Zod — reject malformed data at API boundary
  • OWASP Top 10 — penetration testing
  • Rate limiting — prevent brute-force attacks
Scalability
  • BullMQ — async email, don't block users
  • WebSocket — instant check-in updates
  • GCC — AWS/Azure Singapore region
Business
  • Multi-level approval — coordinator → director
  • Integration tests — automate core flow
