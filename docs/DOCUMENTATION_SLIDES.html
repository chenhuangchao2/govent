01 — Problem Statement

FormSG Collects Data — But Has No Concept of Registration State

Agencies use FormSG to collect event sign-ups. But FormSG is a form builder — once data is submitted, everything else is manual.

No Atomic State

Cannot enforce capacity limits at registration time. No waitlist. No status tracking. Eligibility checked manually after the fact.

Manual Operations

Approval, payment, reminders, attendance — all via email chains and Excel. One coordinator manages everything.

No Audit Trail

No record of who approved whom or when. IM8 governance requires actor-level accountability.

GovEvent automates the entire workflow, with every action auditable and every rule enforced server-side.

Server-Side Eligibility

Email domain, blacklist, and capacity enforced atomically at registration time. Prisma $transaction prevents race conditions.

Automated State Machine

PENDING → Approve → Payment → Check-in → No-Show. Every transition triggers email notification.

Immutable Audit Log

Every organiser action logged with timestamp, actor, and context. Append-only design.

GCC-Portable Architecture

Containerised — currently NorthFlank, portable to GCC-aligned infrastructure (AWS/Azure SG).

Integrations

Resend Outbound

Email at every transition: confirmation, approval, payment link, T-48h reminder, OTP, broadcast. Best-effort — failures don't roll back.

NorthFlank Cron Hourly

Reminders (T-48h), No-Show marking + auto-blacklist, Payment timeout (24h) + waitlist promote. Idempotent via flags.

04 — Data Flow

Registration Lifecycle — End-to-End State Machine

Register → PENDING → Admin reviews → APPROVED or REJECTED or WAITLISTED (if full)
Paid event: APPROVED → PENDING_PAYMENT → Stripe pays → APPROVED | 24h timeout → FAILED → waitlist promoted
Event day: APPROVED → QR scan → ATTENDED | absent → NO_SHOW → ≥5 → Blacklisted

Every transition triggers a Resend email and an audit log entry.

Waitlist auto-promotes when a seat opens (cancel, reject, or payment timeout).

Cron jobs run hourly: reminders, no-show marking, payment expiry. All idempotent.

05 — Assumptions, Limitations & Production Readiness

What This Prototype Is — and What Production Would Require

Prototype Scope

  • Single agency deployment (not multi-tenant)
  • Unclassified data only (no Confidential/Secret)
  • Email as participant identifier
  • Admin accounts managed by Super Admin
  • Stripe test mode — no real payments

Known Limitations

  • No Singpass/Corppass (email + password auth)
  • No real-time push (polling / page refresh)
  • No multi-level approval chain
  • No automated test suite
  • No data retention / deletion policy (PDPA)
  • Single-region (no HA/failover)

For Production

Compliance
  • Singpass/Corppass — national identity verification
  • PDPA — data retention policy, DPIA assessment
  • DSS + WCAG 2.1 AA — Digital Service Standards
  • IM8 — App Security classification before go-live
Security
  • Zod validation on all API inputs
  • OWASP Top 10 penetration testing
  • Rate limiting on auth + registration
Scalability
  • BullMQ — async email queue
  • WebSocket — real-time check-in stats
  • GCC — AWS/Azure Singapore region
Business Logic
  • Multi-level approval — coordinator → director
  • Integration tests — core business flow
06 — How I Built This

AI-Assisted Development — What I Directed vs. What I Fixed

Approach

Claude Code as primary tool. Stitch for design mockups. Key technique: parallel agent execution — 5–8 agents on independent tasks simultaneously.

StageMethod
Schema + APISingle agent — sequential dependencies
Requirements5 agents (PM, compliance, tech, UX, strategy)
Security audit8 audit agents → 6 fix agents
UI rebuildStitch mockups → 5+4+7 build agents
DeploymentSingle agent — sequential debugging

Judgement: Parallel for independent tasks. Sequential for dependencies. Knowing when NOT to parallelise matters.

Where I Overrode the AI

Prisma 5 over 7

AI installed latest. I downgraded — fewer errors with well-documented libs. Version familiarity > recency.

Complete UI rebuild at v5

4 versions of patches → inconsistent UI. Deleted 63 files, rebuilt with a design system. Faster than patching.

No exact capacity numbers

AI showed "45/100 seats". Changed to "Seats Available" / "Waitlist Open" — prevents gaming. My domain judgement.

Dropped Luma → added Stripe

Luma = foreign SaaS. Stripe gives bidirectional data flow: outbound Checkout + inbound webhook.
